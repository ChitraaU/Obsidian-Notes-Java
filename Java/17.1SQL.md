***Why it is important to use Database***
When we store data  Database in the application ,this works temporarily,  the data exists only while the application is running.

If the application stops:

```
Application stops
      ↓
Data in memory is lost
```

A **database** provides persistent storage for application data.

### Why databases are important

- **Persistence** — data remains after the application restarts.
- **Data management** — efficiently store and retrieve large amounts of data.
- **Data consistency** — helps maintain correct and reliable data.
- **Security** — provides mechanisms for controlling access to data.
- **Concurrency** — multiple users/applications can work with data simultaneously.
- **Querying** — allows us to search, filter, sort, aggregate, and manipulate data efficiently.
- **Relationships** — relational databases allow us to model relationships between entities.
***Data, Database ,DBMS***
**Data** is a collection of facts or information that can be stored and processed.
A **database** is an organized collection of data that allows data to be stored, managed, retrieved, and modified efficiently.
**DBMS = Database Management System**
A DBMS is software that allows applications/users to **create, store, retrieve, update, delete, and manage data in databases**.

***DBMS***
- Relational(SQL) ->Relational databases store data primarily in **tables** consisting of rows and columns.
Relational databases are typically accessed using **SQL (Structured Query Language)**.

Examples:

- MySQL
- PostgreSQL
- Oracle
- SQL Server

- Non relational(NoSql)->NoSQL databases don't primarily use the traditional relational table model.

They can use structures such as:

- Documents
- Key-value pairs
- Wide-column stores
- Graphs
Examples:

- MongoDB
- Redis
- Cassandra
- Neo4j
**SQL** is a language used primarily with relational databases, while **NoSQL** refers to a broader family of non-relational database technologies, each with its own query/access mechanisms.

# Inserting Rows

Use `INSERT`.

```
INSERT INTO products
(product_id, product_name, price, category)

(101, 'iPhone 15', 69999, 'electronics');
```
Multiple values can also  be inserted together


# . Showing Data
Use `SELECT`.

```
SELECT * FROM products;
```

`*` means:

> Select all columns.

You can select specific columns:

```
SELECT product_name, price
FROM products;
```

# Showing the Table Structure — `DESCRIBE`

Use:

```
DESCRIBE products;
```

or:

```
DESC products;
```

# Filtering Data — `WHERE`

`WHERE` is used to filter rows based on a condition.

Example:

```
SELECT *
FROM products
WHERE category = 'electronics';
```

SELECT *
FROM products
WHERE category = 'electronics'
AND price > 30000;

This returns only products belonging to electronic

# Sorting Data — `ORDER BY`

`ORDER BY` sorts the result.

### Ascending

```
SELECT *
FROM products
ORDER BY price ASC;
```

### Descending

```
SELECT *
FROM products
ORDER BY price DESC;
```

`ASC` = ascending

`DESC` = descending

# Limiting Data — `LIMIT`

`LIMIT` restricts how many rows are returned.

```
SELECT *
FROM products
LIMIT 5;
```

Returns at most 5 rows.

You can combine it with sorting:

```
SELECT *
FROM products
ORDER BY price DESC
LIMIT 3;
```

Meaning:

> Sort products from highest price to lowest price and return the first 3.

This is very common in real applications.

# `GROUP BY`

`GROUP BY` divides rows into groups based on a column and allows aggregate calculations for each group.

Suppose:

```
product_id | category     | price
-----------|--------------|------
101        | electronics  | 69999
102        | electronics  | 74999
103        | footwear     | 5999
104        | footwear     | 7999
```

If you want the number of products in each category:

```
SELECT category, COUNT(*)
FROM products
GROUP BY category;
```

Result:

```
category      | count
--------------|------
electronics   | 2
footwear      | 2
```

### Mental model

```
GROUP BY
   ↓
Create groups
   ↓
Aggregate each group
```

# `HAVING`

`HAVING` filters **groups** after `GROUP BY`.

Example:

```
SELECT category, COUNT(*)
FROM products
GROUP BY category
HAVING COUNT(*) > 1;
```

Group products by category, count the products in each category, and keep only categories having more than one product.

# `WHERE` vs `HAVING`

This is a **very important interview question**.

### `WHERE`

Filters **individual rows before grouping**.

```
SELECT *
FROM products
WHERE price > 30000;
```

Think:

```
Rows → WHERE → GROUP BY
```

### `HAVING`

Filters **groups after grouping**.

```
SELECT category, COUNT(*)
FROM products
GROUP BY category
HAVING COUNT(*) > 1;
```

Think:

```
Rows → GROUP BY → HAVING
```

### Easy way to remember

> **WHERE → record/row level filtering**

> **HAVING → group level filtering**

Filtering
│
├── Record / Row Level
│       ↓
│      WHERE
│
└── Group Level
        ↓
       HAVING
   
   
***Alias***   
An **alias** gives a temporary name to a column or table in a query.

Use `AS`.

Example:

```
SELECT product_name AS name,
       price AS product_price
FROM products;
```

### Alias with aggregation

Very common:

```
SELECT category, COUNT(*) AS total_products
FROM products
GROUP BY category;
```
