***Dynamic URL***
A **dynamic URL** means a URL whose value changes depending on the resource or request.
Example: 
GET /products/101
GET /products/102 
The {id} represents a dynamic value.

***Path Variables***
They are used to identify a resource and we can pass multiple path variables

`value` specifies **which path-variable name in the URL should be mapped to the Java parameter**.


***Request Parameter/Query Param***
A **query parameter** is passed after `?` in the URL.
Query parameters can be required or optional.
-Mandatory Param
@RequestParam String category The parameter must be present.
-Optional Param
@RequestParam(required = false) String category The parameter may or may not be present.

Query parameters are used to provide additional information, often for **filtering, sorting, searching, pagination**, etc.
required and default value

Query parameters are passed in URL while they are retrieved through request param

***Default Value***

@RequestParam(defaultValue = "electronics") 
String category If the client doesn't provide category, Spring uses "electronics".
So `defaultValue` effectively gives the parameter a fallback value when it isn't supplied.

***Exceptions in Springboot***
An **exception** is an unexpected or exceptional situation that interrupts the normal flow of a program.

In a Spring Boot REST API, exception handling is the mechanism used to:

- Detect failures
- Prevent application crashes from being exposed directly to clients
- Return meaningful HTTP status codes
- Return structured error responses
- Log errors for debugging and monitoring

***Centralized Mechanism for exception handling in Springboot***

Without centralized handling, every Controller might contain code like:

```
try
   call service
catch exception
   create response
```

This leads to:

- Duplicate code
- Controllers becoming large
- Inconsistent error responses
- Difficult maintenance

Spring Boot provides mechanisms to handle exceptions **centrally**.

The common approach is:

```
Controller
    ↓
Service
    ↓
Exception
    ↓
Global Exception Handler
    ↓
HTTP Response
```

These are exceptions that we create according to our application's business requirements,they make the application's buisness failure more meaningful

***Excpetion Handling using Built in Exceptions***

***Exception Handler Annotation***
`@ExceptionHandler` tells Spring:

> **"This method should handle a particular exception."**
### Important

`@ExceptionHandler` can be used:

- Inside a Controller → handles exceptions for that Controller
- Inside a class annotated with `@ControllerAdvice` / `@RestControllerAdvice` → can handle exceptions globally


***Controller Advice And RestController Advice***

`@ControllerAdvice` provides **centralized exception handling and other cross-cutting controller behavior** across multiple Controllers.

`@RestControllerAdvice` is essentially a combination of:

```
@ControllerAdvice
+
@ResponseBody
```

It is particularly useful for REST APIs because the exception handler's return value is written directly to the HTTP response body, typically as JSON.

***Checked and Unchecked Exception***

## Checked Exception

A checked exception is checked by the compiler.

The method must either:

- Handle it using `try-catch`, or
- Declare it using `throws`
Unchecked exceptions occur at runtime and are subclasses of `RuntimeException`.

***Logging***

Logging means recording information about what is happening inside an application.

- Debugging
- Monitoring
- Tracking
Levels of logging : 
TRACE ->Very detailed information.
DEBUG->Detailed information useful during      development/debugging.
INFO->Normal application events.
WARN->Something unexpected or undesirable happened, but the application can continue.
ERROR->A serious failure occurred.

**Logging framework**
Spring Boot applications commonly use SLF4J as the logging API, with Logback as the default logging implementation. Log4j2 is another logging implementation that can be used.
### SLF4J

**SLF4J = Simple Logging Facade for Java**

It provides a common logging API that your application code can use.
### Logback

Spring Boot commonly uses **Logback as its default logging implementation** through its logging setup.

### Log4j / Log4j2

Log4j is another logging implementation/ecosystem.

A common modern setup is **Log4j2**, which can also be used behind SLF4J.
