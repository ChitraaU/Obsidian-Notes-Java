***Prepared statement***

PreparedStatement is a JDBC interface used to execute parameterized SQL statements. It uses placeholders (`?`) for values and helps prevent SQL injection while also allowing efficient reuse of prepared SQL.

While we know Statement is a interface used to execute the Sql queries and Prepared Statement is basically the interface that is used to execute the parameterized Sql queries
It solves the problem of Sql injection

***Transactions***
Transaction is basically a group of operations that are combined as a unit of work and thus that whole unit is called Transaction 
Either the transaction can be committed or rollbacked

***ACID properties***

**ACID** describes four important properties that make database transactions reliable.

```
A → Atomicity
C → Consistency
I → Isolation
D → Durability
```

## A — Atomicity

**"All or nothing."**

A transaction should either complete completely or have its changes rolled back.

# C — Consistency

Consistency means a transaction takes the database from **one valid state to another valid state**, preserving defined rules/constraints.

Consistency can involve things such as:

- Primary-key constraints
- Foreign-key constraints
- NOT NULL constraints
- UNIQUE constraints
- CHECK constraints
- Application/business rules

So:

> **Consistency ensures that valid database rules remain satisfied after a transaction completes.**

# I — Isolation

Imagine two transactions happen at the same time.

```
Transaction A
Transaction B
```

Both are working with the database.

Isolation controls **how much one transaction can see or interfere with another transaction's intermediate work**.

For example:

```
Transaction A:
Update employee salary
       ↓
Not committed yet

Transaction B:
Reads employee salary
```

Should B see A's uncommitted change?

That depends on the database's **isolation level**.

Common isolation levels include:

```
READ UNCOMMITTED
READ COMMITTED
REPEATABLE READ
SERIALIZABLE
```

Each provides a different balance between concurrency and protection from phenomena such as:

- Dirty reads
- Non-repeatable reads
- Phantom reads

For now, remember:

> **Isolation controls the visibility and interaction of concurrent transactions.**

# D — Durability

Once a transaction is successfully committed:

```
transaction.commit();
```

the changes should survive things like a subsequent application restart or normal system failure.
Once committed, the transaction's changes are persistently stored.
