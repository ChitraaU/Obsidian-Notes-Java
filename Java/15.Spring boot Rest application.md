***RestController and GetMapping Annotation***
 The RestController annotation tells which class will be the Rest controller class and it is on the class level

The GetMapping annotation specifies which method would be handling the GET http method requests and it is on method level.

***Request Mapping***
`@RequestMapping` is used by Spring to **map incoming HTTP requests to a controller class or a controller method**.

It can be used at:

- **Class level** ✅
- **Method level** ✅
- **Both together** ✅
### 1. Class level

At the class level, it is commonly used to define a **common/base URL** for all the endpoints inside that controller.

```
@RestController
@RequestMapping("/students")
public class StudentController {
    
```

### 2. Method level

At the method level, `@RequestMapping` can map a request to a **specific method**.

For example:

```
@RequestMapping(value = "/all", method = RequestMethod.GET)
public String getStudents() {
    return "Students";
}
```

This means:

```
GET /students/all
       ↓
getStudents()
```

So yes, it determines **which method should handle the incoming request**.

---

### 3. Multiple HTTP methods

This is another thing you correctly noticed.

`@RequestMapping` can be configured to handle different HTTP methods:

```
@RequestMapping(
    value = "/students",
    method = {RequestMethod.GET, RequestMethod.POST}
)
```

This endpoint can handle both:

```
GET  /students
POST /students
```

However, Spring provides more specific annotations that are usually easier to read:

```
@GetMapping
@PostMapping
@PutMapping
@DeleteMapping
```

These are essentially more specialized versions of `@RequestMapping`.

For example:

```
@GetMapping("/students")
```

is conceptually equivalent to:

```
@RequestMapping(
    value = "/students",
    method = RequestMethod.GET
)
```

Creating a POST endpoint 
To create a Post endpoint firstly we use @PostMapping with the specific method that has to be exposed to perform that action and then if we have to do it for a specific id or anyother object we can specify it with the help of Pathvariables

Request -> Request Header+Request Body
A Request contains the Request header and the Request Body in the Body for the Rest Api's it is generally in the form json and it also includes the request method/line and URL
Response-> Response Header +Response Body
While a response also contains Response Header and the Response Body and for the Rest Apps it is in the form json and it also includes the status code

Creating a PUT endpoint : to create a Put endpoint we use @PutMapping with the specified method

Creating a Delete endpoint : To create a Delete endpoint we use @DeleteMapping

Response Entity = HTTP Response +Status code
`ResponseEntity` gives us control over the HTTP response — body, status code, and headers.

HTTP Status: HTTP status codes can of different types like 404,201, 500 etc
