***What is Relationships in a database and why it is important***
A **relationship** defines how records in one table are connected to records in another table.
It solves the problem of 
- data duplicity
- Data inconsistency
- Better data organization
- Easier querying using JOIN
- A proper representation of real-world entities

***One to One relationship***
One record in Table A is associated with one record in Table B.
### `@OneToOne`

This tells JPA:

> "This entity has a one-to-one relationship with another entity."

### `@JoinColumn`

`@JoinColumn` tells JPA which column should be used as the **foreign key**.

***Mapped By***
`appedBy` means:

> **"The other entity owns/manages the relationship. I am just the inverse side."**


It refers to the **Java field/property** in the other entity.
@OnetoOne(mapped by ="",Cascade)

# Cascade

You'll see:

```
cascade = CascadeType.ALL
```

Cascade controls whether certain operations performed on one entity should also be propagated to its related entity.

For example:

```
Customer
   |
   ↓
Address
```

If you save a new Customer and cascade persist is configured, JPA can also persist the associated Address.

Common cascade types include:

|Cascade|Meaning|
|---|---|
|`PERSIST`|Save/persist related entity|
|`MERGE`|Merge related entity|
|`REMOVE`|Delete related entity|
|`ALL`|All cascade operations|

### Important

Don't blindly use:

```
CascadeType.ALL
```

especially with relationships where deleting one entity shouldn't delete another.

For example, deleting a **Customer** shouldn't necessarily delete historical **Transactions**.
> **Cascade defines whether JPA operations performed on one entity should automatically be propagated to its related entities.**

And one important distinction:

**`mappedBy` → tells JPA who owns/manages the relationship.**

**`@JoinColumn` → identifies the foreign-key column.**

**`cascade` → tells JPA which entity operations should propagate across the relationship.**


***One to many and Many to One relationship***
One record is associated with **multiple records** and vice verse
### Very important interview concept

These two commonly appear together:

```
Customer
@OneToMany
List<Account>

Account
@ManyToOne
Customer
```

This represents a **bidirectional one-to-many relationship**.


***Many to many relationship***
Multiple records on both sides can be associate
 and we use JoinTable to represent it as a new table is created in the process.
 
# `@JoinTable`

In JPA, `@JoinTable` tells Hibernate about that intermediate table.

Conceptually:

```
Student
   ↓
@JoinTable
   ↓
student_course
   ↓
Course
```

The join table contains the foreign keys:

```
student_id
course_id
```

So:

- `@JoinColumn` → usually represents a foreign-key column directly associated with an entity
- `@JoinTable` → represents an intermediate/join table, commonly used for many-to-many

# `@JsonIgnore`

This one is **not a JPA relationship annotation**.

It's related to **JSON serialization**, commonly when using Jackson in Spring Boot.

This becomes important with bidirectional relationships.

For example:

```
Customer
   ↓
Account
   ↓
Customer
   ↓
Account
   ↓
Customer
   ↓
...
```

If Spring tries to convert this entire object graph into JSON, you can end up with **infinite recursion**.

For example:

```
{
  "customer": {
    "accounts": [
      {
        "customer": {
          "accounts": [
            ...
          ]
        }
      }
    ]
  }
}
```

`@JsonIgnore` can tell Jackson:

> Don't include this particular property when converting the object to JSON.

So it's commonly used to prevent circular JSON responses.

## Your complete relationship cheat sheet

|Annotation|What problem does it solve?|
|---|---|
|`@OneToOne`|One entity ↔ one entity|
|`@OneToMany`|One entity → many entities|
|`@ManyToOne`|Many entities → one entity|
|`@ManyToMany`|Many entities ↔ many entities|
|`@JoinColumn`|Specifies the foreign-key column|
|`@JoinTable`|Creates/uses an intermediate table for a relationship|
|`mappedBy`|Says the relationship is managed by the field on the other side|
|`cascade`|Propagates JPA operations to related entities|
|`@JsonIgnore`|Prevents a field from being included in JSON|
