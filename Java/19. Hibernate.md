***Intro to ORM ,Hibernate, JPA vs JDBC***
***ORM->Object Relational Mapping***
It is a technique that maps the Java Classes/Objects into tables in the Relational databases and vice versa
Java Application ↔ ORM ↔ Relational Database

Hibernate is an ORM framework that implements the JPA specification. It maps Java classes/objects to database tables/rows and handles the conversion between them.

Your Java Code 
↓ 
JPA (rules/specification) 
↓ 
Hibernate (implementation/tool) 
↓
Database

Problems with JDBC
- Large Boilerplate code
- Manual mapping
- Error prone
- Hard to evolve
### JPA vs Hibernate

| JPA                                         | Hibernate                     |
| ------------------------------------------- | ----------------------------- |
| Specification                               | Implementation                |
| Defines rules/interfaces                    | Implements those rules        |
| Provides annotations like `@Entity`, `@Id`  | Executes the ORM operations   |
| Doesn't directly interact with DB by itself | Actually communicates with DB |
| Standard                                    | Framework/tool                |

| Task                       | Without ORM                                     | With ORM                                         |
| -------------------------- | ----------------------------------------------- | ------------------------------------------------ |
| Insert a User              | Write Insert Sql manually                       | save(user)                                       |
| Get all users              | Write select, map resultset manually            | findall()                                        |
| Handle relationships       | Write complex joins ,nested loops               | Use onetomany , manytomany-automatic mapping     |
| Schema changes             | Update Sql in every query                       | ORM can auto adapt or run migrations             |
| Transactions  and Sessions | Manually open,close connections, manage commits | ORM manages sessions &transactions automatically |
***Hibernate Architecture and Components***

| Layer/Component                         | Role in Architecture                                                         |
| --------------------------------------- | ---------------------------------------------------------------------------- |
| Entity                                  | Java class mapped to a database table                                        |
| Configuration & Mapping files           | Define DB connections + entity mappings                                      |
| SessionFactory                          | Heavy app wide factory that manages database connections and create sessions |
| Session                                 | Light Weight per request object for CRUD and persistence operations          |
| Transactions                            | Manages commit/rollback of DB changes                                        |
| Persistence Context(1st level of cache) | Tracks and synchronises entity inside a session                              |
| (Optional )2nd level cache              | Shared cache across sessions for perfromance                                 |
| Database                                | Actual storage layer                                                         |


### The key distinction

|JDBC|Hibernate|
|---|---|
|`Connection`|`Session`|
|`Statement` / `PreparedStatement`|Hibernate handles SQL execution internally|
|SQL written manually|SQL generally generated by Hibernate|
|`ResultSet`|Hibernate maps DB results to entities|
|Manually map rows → objects|ORM does the mapping|
